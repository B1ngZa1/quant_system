# 执行走廊研究原型：上线就绪度审计

**日期：** 2026-09-22  
**范围：** `research/models/execution_corridor_baseline.py`、其 20 项测试、执行走廊设计文档及现有后端回测边界。  
**结论：** 原型可作为研究基线和教学/设计证据，**不具备实盘、自动下单或收益宣称的上线条件**。

## 已验证范围

- `python -m pytest -q -p no:cacheprovider research/models/test_execution_corridor_baseline.py`：20 项通过。
- 原型将候选数量先经过容量、参与率、持仓和风险预算等约束；风险降低逻辑由持仓前状态推导，不再接受调用方传入的“风险降低”布尔绕过标记。
- 项目未接入券商、交易所、Binance、API 密钥、账户或真实订单接口。
- [执行走廊模型](../models/EXECUTION_CORRIDOR_MODEL.md) 已定义：高度＝执行紧迫度，路口＝重估/状态切换点，变道＝路由、策略或订单类型切换，容量＝流动性与风险约束。

## 仍未满足的生产门槛

| 优先级 | 缺口 | 为什么不能忽略 | 需要的下一步 |
| --- | --- | --- | --- |
| P1 | 风险快照、价格和容量当前仍可由调用方提供 | 策略侧若传入过期或不实状态，研究原型无法独立证明约束输入真实 | 引入版本化、不可变的 `RiskSnapshot`/成交账本，由独立风险服务签发并审计 |
| P1 | “高度”、市场状态、路由和订单类型尚未形成统一可执行状态机 | 文档语义完整不等于实际路由策略、最小停留时间或切换成本已经实现 | 以可复现数据实现状态检测、滞回、切换成本与回退基线 |
| P1 | 多 Agent 聚合尚未实现 `agent_id` 级归因、组合聚合、行业/相关性/保证金/CVaR/自成交保护 | 单标的数量截断不能证明组合级风险受控 | 将 CTDE 输出限定为候选，先做内部净额、统一风险投影与完整审计事件 |
| P1 | 回测整合尚未证明无同棒 OHLC 未来函数、无重复交易成本或正确的既有持仓风险评估 | 即使原型测试通过，也不能替代真实历史数据上的系统级验证 | 使用 point-in-time 数据、事件驱动撮合、部分成交、费用/点差/滑点/冲击、walk-forward、purged/embargo 和容量压力测试 |

## 处理边界

本审计不修改既有产品后端或用户未提交代码。这里记录的风险不是对当前回测结果的收益判断，也不授权修复范围之外的改动。任何后续实现都应保持以下顺序：

1. 先核验数据许可、复权、退市、可用时间和市场日历；
2. 再实现事件级模拟和独立风险账本；
3. 然后以预注册指标进行样本外和压力测试；
4. 最后才允许 RL/多 Agent 提出候选动作，并始终保留人工审批边界。
