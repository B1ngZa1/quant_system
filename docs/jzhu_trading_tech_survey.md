# jzhu-trading 技术调研文档

## 1. 整体架构设计模式
jzhu-trading（小宇量化）项目采用了混合式的架构设计：
- **微服务与单体结合**：标准模式下，采用 Spring Boot 微服务架构；同时提供 Lite 模式（All-in-one），将 6 个核心 Java 服务和网关合并为一个应用，极大降低了本地部署和运行的资源消耗。
- **领域驱动设计（DDD）思想**：从代码结构和命名（如 `CleanupOldKlinesUseCase`、`GetStockListUseCase`）可以看出，项目应用了 Clean Architecture 和 DDD 思想，将业务逻辑（Use Cases）与底层实现隔离。

## 2. 技术栈选型
- **后端**：Java 17+, Spring Boot
- **数据库**：TimescaleDB（基于 PostgreSQL），专为处理海量时间序列数据（如 K 线数据）优化。
- **前端**：独立 Web 应用（镜像 `web-app`），推测为 React 或 Vue 的单页应用（SPA）。
- **策略引擎**：基于 **Groovy** 脚本引擎，支持策略代码的动态加载和执行，无需重新编译主程序。
- **基础设施**：Docker & Docker Compose，容器化部署。
- **数据源**：集成 AKTools 和 Baostock，获取A股、港股、美股数据。

## 3. 模块划分方式
- **K线模块（K-line）**：处理 1 分钟到月线等 7 种不同周期的 K 线数据，支持历史数据自动清理以释放空间。
- **指标计算模块（Indicator）**：内置 MA、MACD、RSI、BOLL 等技术指标的计算逻辑。
- **策略管理模块（Strategy）**：负责策略的 CRUD 操作、版本管理以及 Groovy 策略脚本的运行与结果收集。
- **股票基础模块（Stock Basic）**：处理股票列表的获取、延迟加载（Lazy Loading）以及缓存。
- **系统配置模块（System Config）**：通过 K-V 形式管理系统运行时配置和状态。

## 4. 数据流管理机制
1. **数据采集**：后端服务（如 `baostock-svc`）或集成的 AKTools 容器，从外部数据源拉取实时及历史行情数据。
2. **数据存储**：数据流入 TimescaleDB，利用其 Hypertable 特性，按时间戳（ts）字段进行自动分区（Partitioning），保证海量数据的写入和查询性能。
3. **数据预热**：内置 `PreloadJobRunner` 异步任务，提前加载活跃股票数据至内存或缓存，降低请求延迟。
4. **前端展示**：前端应用通过 API 网关（如 8180 端口）请求后端，获取数据或提交策略执行指令。

## 5. 错误处理与日志记录规范
- **错误处理**：
  - 数据库初始化采用幂等脚本（`IF NOT EXISTS`），支持反复执行不出错。
  - 容器启动依赖健康检查（Healthcheck），例如 `pg_isready`，确保依赖服务就绪后再启动应用。
- **日志记录**：
  - 日志主要输出至容器的标准输出，便于 Docker 统一收集。
  - 业务日志和错误日志通过 `app.log` 和 `error.log` 分别记录，便于排查异常。
- **系统维护**：内置定时任务清理过期数据并执行 `VACUUM`，避免数据库膨胀导致系统崩溃。

## 6. 配置管理与部署流程
- **配置管理**：
  - 环境变量：通过 `docker-compose.yml` 传递数据库密码、API 密钥等敏感信息。
  - 运行时配置：存储于数据库的 `system_config` 表中，支持动态调整。
  - 系统标识：持久化在 `config/.system-id` 中，独立于数据库目录，防止数据卷重建时丢失。
- **部署流程**：
  - 提供了一键启动脚本（`start.bat` / `start.sh`）和重启/停止脚本。
  - 通过 Docker Compose 编排多个容器（数据库、后端应用、前端应用），自动拉取阿里云镜像仓库的最新镜像，并映射挂载持久化目录（`data/`, `config/`）。

## 7. 优劣势对比与重构启示
- **优势**：TimescaleDB 的引入极大提升了 K 线数据的处理能力；Groovy 动态脚本引擎提升了策略开发的灵活性；Lite 模式兼顾了个人开发者和小型团队的资源限制。
- **劣势**：Java 体系在量化领域的生态略逊于 Python（如 Pandas, NumPy 等）；强依赖容器环境，本地调试存在一定复杂度。
- **重构启示**：在当前 `quant_system` (Python/FastAPI) 中，可借鉴其基于时间序列的存储方案、动态策略引擎思路、以及清晰的用例（Use Case）驱动的领域分层架构，并补充更为完善的可观测性和自动化测试机制。
